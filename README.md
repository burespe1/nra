# NAP Reference Architecture (NRA) – model repository

Enterprise Architect model of the NAPCORE NAP Reference Architecture, its generated documentation and change history.

## Layout

| Path | Content |
|---|---|
| `model/NRA.qea` | The EA model (one file, Git LFS, lockable). Versions are commits and tags, not file copies. |
| `export/` | Text export of the model, generated by `tools/export.py`: one YAML file per package (elements, notes, tagged values, links), `diagrams.yaml`, `glossary.yaml`, `templates/`. This is what you read in diffs and pull requests. |
| `docs/` | Generated documentation and change protocols per release. |
| `changes/` | Imported review documents: proposed changes (`changes.yaml`) and their report (`changes.md`) per review. |
| `CHANGELOG.md` | One section per release, newest first. Details are in the change protocol of each release. |
| `tools/` | `export.py` (model → text), `diff.py` (change report between two versions), `check.py` (modelling rules, Guideline 07), `docx_import.py` / `docx_apply.py` (review in Word → model), `hooks/pre-commit`. |
| `.github/workflows/model-diff.yml` | On every pull request: change report and model check as PR comment; on every `v*` tag: report against the previous release. |

## Versioning

- The model as a whole uses Semantic Versioning (`vMAJOR.MINOR.PATCH`), the NRA stays in the 2.x line.
- Each element carries the tagged value `revised` (date of the last **approved** change) and, if created after 2.1.0, `since` (version of first appearance). EA's own modified date is not used – it changes on every save.
- Element identifiers (EA GUIDs) never change.

## Working with the model

One-time setup:

```powershell
git clone https://github.com/burespe1/nra.git
cd nra
git lfs install
git config core.hooksPath tools/hooks      # re-exports the model on every commit
```

A change (replaces the `unlocked.docx` procedure):

```powershell
git switch main; git pull
git switch -c wg463-org-view               # one branch per work item
git lfs lock model/NRA.qea                 # makes the file writable, others see who works on it
# ... edit model/NRA.qea in Enterprise Architect, close EA ...
git add model/NRA.qea
git commit -m "Org view: descriptions of actors and roles (WG 4.6.3)"   # hook updates export/
git push -u origin wg463-org-view
git lfs unlock model/NRA.qea
```

Then open a pull request. The workflow posts the change report (new objects, title/description changes, connections, tagged values, templates) as a comment; reviewers can also read the YAML diff of `export/`. The same comment contains the result of `tools/check.py`: **errors** (missing Keywords or `revised`, IN/OUT against the arrow, reversed componentof, published requirement without «fulfilled by», …) must be fixed before merging, **warnings** are reviewed.

Release:

1. Merge the pull requests, set `revised` to the approval date on the changed elements.
2. Generate the documentation in EA (master document *National Access Point Reference Architecture*, cover *NAPCORE Cover*, style *NAPCORE Style*), put it and the change protocol in `docs/`.
3. Update `CHANGELOG.md`, commit, tag: `git tag -a v2.2.0 -m "NRA v2.2.0"; git push --tags`.

Local change report and check without GitHub:

```powershell
python tools/check.py model/NRA.qea check.md      # --strict: exit code 1 on errors
python tools/diff.py --git v2.1.0 HEAD report.md
python tools/diff.py old.qea new.qea report.md
```

## Review in Word (offline)

Views can be reviewed in a generated Word document and transferred back automatically:

1. Generate the document from a tagged version (e.g. `NRA-2.2.0-review-OrgView.docx`). Reviewers work with **Track Changes** on and do not touch the line *Revised/Last changed …, GUID: {…}* – it anchors each element.
2. TODOs and questions are **Word comments**: `TODO …` becomes an EA task on the element, other unresolved comments become EA issues (Maintenance tab; not printed in the documentation). New elements are written as a new heading without GUID.
3. Import and review the proposal:
   ```powershell
   python tools/docx_import.py review.docx model/NRA.qea --out changes/2026-11-orgview/changes
   ```
   `changes.yaml` lists every changed element (name, new note, change type, authors, comments); set `apply: false` to skip one. `changes.md` shows the text diff.
4. Close EA and apply: `python tools/docx_apply.py review.docx <base>.qea model/NRA.qea --changes changes/…/changes.yaml`. Names, notes, package descriptions, Status = Proposed and `revised` are written; new elements, connection changes and conflicts (element changed in the model meanwhile) are done by hand in EA following the report.
5. Commit, push, pull request – the change report shows the result.

Pilot: `changes/pilot-2.0-orgview` – the WG 4.6.3 comparison document imported against v2.0 reproduces the manually entered v2.1.0 texts (19 of 20 elements ≥ 99 % identical).

## Notes

- `.qea` files cannot be merged. Never edit the model on two branches at the same time – the LFS lock prevents it.
- Rules for versioning and modelling: guidelines 06 and 07 (`C:\work-AI\NRA\guidelines`).
- Requirements: Python 3 (standard library only), Git, Git LFS.
